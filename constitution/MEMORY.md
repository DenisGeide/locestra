# Правила памяти

- Статус: нормативный документ; Controlled Memory Engine реализован на этапе 003, scoped Knowledge Engine — на этапе 004; новые consumers не расширяют scope/disclosure автоматически.
- Владелец: владелец платформы.
- Назначение: допустимые данные, provenance, жизненный цикл и выдача памяти.
- Применение: текущая task SQLite и будущий Memory Engine.
- Изменение: после privacy/security review и migration tests.

## Разделение данных

Не смешивай:

- task state и tool evidence;
- подтверждённые пользовательские предпочтения;
- project facts и индекс репозитория;
- архив импортированных материалов;
- временный активный контекст;
- предположения и model-generated summaries.

## Обязательные свойства

Каждый долгоживущий факт имеет источник, scope, время, status/confidence и способ обновления или удаления. Свежий файл или tool result отменяет противоречащую память. Неподтверждённый вывод не становится фактом автоматически.

Память должна поддерживать просмотр, исправление, экспорт, soft delete и окончательное удаление. Данные одного проекта не выдаются другому без разрешённой связи.

## Запрещённые данные

Не сохраняй токены, пароли, cookies, private keys, содержимое `.env`, credentials, секретоподобные строки и нерелевантные приватные данные. Логи и exports проходят redaction.

## Текущий предел

Текущая `data/memory.sqlite3` хранит только task records и не является долгосрочной персональной памятью или RAG. До этапа 003 нельзя заявлять обратное.

## Критерий изменения

Изменение схемы требует versioned migration, backup/restore fixture, scope/privacy tests и обновления [SYSTEM_MANIFEST.md](../SYSTEM_MANIFEST.md).
