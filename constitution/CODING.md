# Правила программирования

- Статус: нормативный документ.
- Владелец: владелец платформы.
- Назначение: безопасное чтение, изменение, проверка и review репозиториев.
- Применение: Qwen Code, Codex, gateway coding routes и coding tests.
- Изменение: после coding regression и review; Git/publish permissions не могут быть ослаблены локальным prompt.

## До работы

- Уважай явно заданный путь. Несуществующий явный путь не заменяй default-проектом.
- Определи Git root и прочитай все применимые `AGENTS.md`.
- Для read-only задачи не изменяй файлы и не запускай команды проекта, если пользователь запросил только чтение/перечень.
- Сохраняй пользовательский dirty worktree; не выполняй reset, checkout, stash или cleanup чужих изменений.
- До мутации зафиксируй цель, ограничения и acceptance criteria.

## Исполнение

- Простые и средние coding-задачи выполняет локальный coding-agent на сильном локальном профиле.
- Сложные, архитектурные, security- и высокорисковые задачи могут быть переданы Codex согласно [разрешениям](../docs/PERMISSIONS.md) и классификации данных.
- Чистый review выполняется read-only; `review and fix` является изменяющей задачей.
- Команды передаются как список аргументов, с timeout, ограниченными попытками и сохранённым exit code.
- Два исполнителя не изменяют один worktree одновременно.
- Исполнитель не создаёт commit, если задача это запрещает. Push, deploy и publish без явного разрешения запрещены всегда.

## Проверка и завершение

Минимум: проверить ожидаемые файлы, `git diff --check`, релевантный тест и полный diff. По необходимости добавь lint, typecheck, build, browser QA и secret scan. Различай `passed`, `failed`, `not_run` и `not_applicable`.

Reviewer проверяет исходную цель, acceptance criteria, diff, test evidence, лишние изменения, безопасность и разрешения. Текстовый отчёт исполнителя не заменяет эту проверку.

## Handoff

Handoff сохраняет исходную цель, project/commit/worktree, правила, критерии, релевантный контекст, diff, выполненные проверки, точные ошибки и оставшиеся действия. Секреты и нерелевантные приватные данные исключаются.

## Критерий изменения

Любое изменение coding policy требует воспроизводимого fixture, regression test и подтверждения, что пользовательский worktree и `/v1` boundary не регрессировали.
